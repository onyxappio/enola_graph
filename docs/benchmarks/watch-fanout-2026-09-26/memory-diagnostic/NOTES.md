# Initial memory investigation (diagnostic only)

The accepted-for-correctness 63c037d combined binary and fanout-only control were run once each with GODEBUG=gctrace=1 and ENOLA_GRAPH_PROFILE=1, keeping GC policy unchanged. Shared host, not acceptance timing. In this diagnostic pair control peak RSS was 1,321,582,592 bytes and combined was 1,180,614,656 bytes, reversing the direction of the earlier repeated cohort; this does not cancel its failed RSS gate. Max live heap sampled at GC boundaries was 450 versus 417 MiB. There is not yet evidence of a stable retained-memory regression caused by configuration discovery.

Both profiles show a final heap rise around checkpoint JSON encoding (~71 MB JSON). The previous write path uses json.Marshal, whose result duplicates the internal encoder buffer. A proposed write-path optimization uses json.Encoder, removes only its final newline through a one-byte lookbehind writer, and hashes the exact bytes written. It retains the existing byte format, fsync/rename/pending promotion and failure semantics. Encoder still buffers the full JSON value; this is not a bounded-memory serializer and adds no relationship index.

Focused tests check byte/fingerprint equality, encoding and short/error writes, and the existing refused-transaction invariant. A synthetic 4,000-file benchmark measured approximately 4.73 MB/op for marshal versus 3.00 MB/op for encoding to a writer; this is allocation evidence, not process-RSS acceptance. Product NATS correctness has now passed seven calls/four gates and exact seven-scenario cross-build hash equality; full repository validation also passed (110 packages, exit 0); repeated timing remains pending. The correctness-only run observed 1118.2 MiB initial RSS, but is not a timing/acceptance cohort. Its raw absent-first-batch sentinel is retained; the next harness represents missing batches as null.

The diagnostic observer was stopped after producer completion and its consumer log was empty; these runs are GC/RSS diagnostics only, not independent consumer-equivalence evidence. Earlier acceptance correctness receipts remain authoritative for the unmodified binaries.
